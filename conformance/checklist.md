# 12. Core Profile Conformance Checklist

An Implementation conforms to the Core Profile if and only if it implements: the registry with rules R1–R4; social-proof tiers 1–3 with the identity floor and device attestation of §4.1 (tier 4 ceremonies MAY be simulated); Credential types 1–6, 8–12 with the cross-cutting claims (type 7 MAY be folded into 12 for a single-examination deployment); the three process ceremonies of §7 with verify-then-decrypt ordering enforced; the event schema of §8 with rules E1–E5; one context node operating fully offline through a complete conduct cycle with successful federation on reconnect; the physical-bridge requirements of §10 for at least one paper-delivered context and, RECOMMENDED, one device-delivered session demonstrating the bridge's retirement; and security considerations S1–S5 without exception. An Implementation MUST additionally declare the profile it conforms to; conformance is always stated as core plus a named profile (e.g. "Pariksha Core, Examination Profile — India, draft-01").

Everything beyond this checklist — multi-form assembly, item banks, equating, per-candidate delivery at scale, agentic orchestration — is later rungs of the same kernel: new claims and new receivers, no new nouns, no new verbs.
